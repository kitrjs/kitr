# kitr without React

`kitr new my-api --kit server` creates a backend whose dependency graph contains no React, no TanStack and no Vite:

```
my-api/
  server.ts              # createServer({ providers, config }) + listen()
  kitrrc.ts              # providers: logger, db
  config/                # one file per package; config/index.ts is generated by `kitr add`
  start/routes.ts        # defineRoutes(...)
  start/socket.ts        # createSocketServer({ channels })
  app/controllers/       # plain classes, one per resource
  app/channels/          # defineChannel(...)
  app/env.ts             # createEnv({ server: { PORT, LOG_LEVEL, DATABASE_URL } })
  test/                  # createTestClient(server).get('/api/health')
```

Run it with `pnpm dev` (tsx watch) or `pnpm start`. `kitr api:sync` writes `openapi.json` and a route table; `kitr routes:list` prints the routes.

## What you get

- **Router**: `defineRoutes` with groups, prefixes, named routes, `resource('projects', Controller)` for the five REST actions, per-route and per-group middleware (`cors()`, `rateLimit()`, `requireJson()`, your own `defineMiddleware`).
- **Controllers**: classes whose methods take an `HttpContext` (`params`, `query`, `body`, `request`, `response`, `locals`, `logger`, `requestId`, `app`). `static validation = { store: { body: schema } }` validates before the method runs and types the client.
- **Errors**: throw `KitrError.notFound('Project')`, `KitrError.validation(fieldErrors)` or anything else; every response has the same `{ code, message, status, fieldErrors? }` shape the client already understands.
- **Lifecycle**: providers run `register → boot → ready → shutdown`; `server.listen()` wires SIGINT/SIGTERM to `shutdown` with a timeout. The request-scoped container (`useRequestApp()`) forks the app per request.
- **Sockets**: `createSocketServer({ channels, authorize })` on crossws; `sockets.use(channel, params).emit(event, data)` from a controller. The client side (`kitr/socket`) can live in any frontend, kitr or not.
- **Auth**: `kitr/auth/server` gives `authMiddleware({ verify })`, `requireUser()`, `currentUser()` and `can()` on the API side with the same `defineAbilities` the client uses.
- **Database**: `defineDb({ connect, disconnect })` in `config/db.ts` with the ORM of your choice; no ORM is bundled.
- **Typed client for the frontend**: `export type AppRoutes = typeof routes.$types` in the backend, `createApiClient<AppRoutes>()` in the frontend. Share the type through a workspace package or a `.d.ts`; there is no generated code to keep in sync.

## Mixing

A kitr React app that later needs its own backend keeps the same packages: `kitr add server api` turns it into a TanStack Start app where `app/routes/api.$.ts` forwards `/api/*` to the kitr router. A standalone backend plus a `--kit app` frontend is the other valid shape; `kitr doctor` keeps React out of the backend either way.
